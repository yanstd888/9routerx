# Command Code Provider API native lane
Add the isolated `command-code` provider from OmniRoute pin `632d84f569f72893ed148e5b19dd05e2fff1a52a`, alias `cmd`, display name "Command Code", terminal icon, color `#111827`, and all 22 pinned Provider API model ids. Bearer API-key requests go to the pinned `https://api.commandcode.ai/provider/v1/chat/completions`; the six `targetFormat:"claude"` models go to `/provider/v1/messages` with `anthropic-version: 2023-06-01`, with OpenAI chat bodies converted through the existing Claude Messages shaper and Claude replies translated back. A client-supplied output cap is clamped to 200000, a missing or non-positive cap uses the pinned reasoning-safe 16384 default, and model ids are normalized only for the two documented bare `mimo-v2.5` aliases. Responses clients are translated to the Chat surface through the router's Responses bridge; the pin's separate `/provider/v1/responses` route and the CLI `/alpha/generate` fallback are deliberately not used, so no CLI impersonation headers are emitted. No credential is sent to any other lane and no `cmc`/`commandcode` behavior changes. Pin ships no artwork, so `web/public/providers/command-code.png` is a 128x128/3027B glyph generated only from pinned `textIcon "CC"` and color `#111827`. Verification: offline httptest fixtures pin chat-path Bearer auth, CLI-header isolation, model/token normalization for id and alias overrides, Messages-lane Anthropic header and tool shaping, Claude-to-OpenAI response translation, plus frontend registry/metadata/model/artwork assertions. No live provider, login or quota validation was performed.
